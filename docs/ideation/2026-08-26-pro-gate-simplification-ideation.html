Ideation

pro-gate simplification

Replace caller-side interpretation with a few engine-owned facts. Keep the machinery that proves identity, preserves charged work, and bounds spend; delete the questions, polling rituals, and duplicated policy prose built around it.

Grounding Context

Codebase Context. Current truth is origin/main at f2dfe5f. pro-gate has durable safety state in the engine, but terminal interpretation is distributed across SKILL.md, oracle-reviewer.md, the daemon prompt, and shell exit/status surfaces. The skill and engine also make partly independent continuation decisions: caller prose uses verdict and finding semantics; the engine grants a base three rounds, earns more on shrinking open P0/P1 counts, brakes after two non-shrinks, and never exceeds eight.

The strongest direct example is the supplied PR #1983 transcript: after a connector could not verify the PR, the agent prepared a smaller exact-head bundle and then blocked on whether to spend a forced round. The question was unnecessary process even if the correct answer was “stop”; the system should have emitted an authoritative disposition rather than converting ambiguity into operator permission.

Evidence limit: the session-history corpus was degraded. Cass had a malformed canonical database, a stale lexical index, and 108 quarantined conversations. The readable evidence verified one bounded two-run stop and one premature/ambiguous recovery result, but it did not verify an endless same-head loop or a recurring authorization-question pattern. Ideas that required those stronger claims were cut.

Preserved boundary. Nonce/provenance, reservation ownership, no-respend recovery, write-once artifacts, charge ordering, and a finite engine-level spend ceiling are safety mechanisms—not ceremony. The simplification target is the duplicated caller policy and protocol around them. External workflow-engine, controller, and SRE prior art reinforces the same shape: immutable input identity, typed outcomes, re-observation before action, and retries that cannot silently promote into semantic spend.

1. Terminal disposition, not terminal question

Terminal ownershipConfidence 94%Complexity Medium
Description
Persist one marker-addressed terminal disposition that binds reviewed input identity, verdict, unresolved findings, spend and round state, branch-preservation rule, next actor, and exactly one permitted next transition. NEEDS-DISCUSSION becomes either a named safe action or a compact, specific human decision—not a generic permission question.
Basis
direct: current code captures verdicts while the skill separately determines terminal behavior; durable marker, artifact, and status machinery already exists.
Rationale
This directly fixes the supplied failure with the smallest authoritative seam. It lets agents continue whenever policy already authorizes the next move while preserving the branch and stopping spend when judgment is genuinely external.
Downsides
The disposition vocabulary becomes a compatibility contract. The engine must report authority boundaries without accidentally granting merge or fix authority it does not own.

2. Zero-spend observer replaces caller polling

Run observation and recoveryConfidence 92%Complexity Medium
Description
Add a marker-addressed blocking observer that follows durable state, emits meaningful transitions, and returns a typed terminal observation. It cannot dispatch, reserve, substitute input, or impose a submission timeout; observer death leaves the charged run and recovery artifacts intact.
Basis
direct: the skill, relay, and daemon each narrate their own polling and harvest loop despite atomic state publication and durable no-spend recovery.
Rationale
Waiting is control-plane labor, not judgment. Moving it into a zero-token process deletes repeated agent turns, hand-written pollers, and elapsed-time interpretation without touching nonce, reservation, or artifact guarantees.
Downsides
The observer must be proven incapable of dispatch and lifecycle ownership. A stale, unmerged --wait branch exists, but it is historical evidence—not code to revive blindly.

3. Exact-input passport for every verdict

Identity and spend safetyConfidence 89%Complexity Medium
Description
Bind every result, reservation, capture, round record, disposition, and handoff to one immutable review-input identity: canonical repository and PR, exact head when applicable, normalized bundle or diff digest, mode, policy version, spend key, and marker. Old work remains recoverable but is explicitly superseded for changed input.
Basis
direct: runtime markers and nonce prove attempt and prompt provenance, but current runtime identity does not prove exact-head applicability.
Rationale
Deepening one invariant makes surrounding exact-head narration, hashes pasted into comments, and manual “is this still current?” ceremony deletable. Provenance answers who produced the review; the passport also answers what it still applies to.
Downsides
Normalization across connector, bundle, and both modes is subtle. Existing artifacts need a compatibility state rather than being declared current or discarded.

4. Typed outcomes and generated action cards

Agent-facing protocol surfaceConfidence 88%Complexity Medium
Description
Promote engine state to a stable typed outcome containing category, reason, spend or retry class, currentness, actor, exact safe command or capability, and artifact references. Render concise human and agent action cards from it. Keep audience-specific judgment prose hand-written and use targeted contract tests rather than compiling every document.
Basis
direct: current status exposes rich internal classifications as a boolean recoverable plus free-text next_step; skill, relay, and daemon independently translate exits and phases and have already drifted on the default round policy.
Rationale
One semantic contract lets callers delete parsing and synchronized state-to-action narratives. It also makes failure behavior testable at the contract boundary rather than through prompt archaeology.
Downsides
Schema evolution becomes public API work. Rare recovery states still need rich diagnostics, so typed outcomes should front the system rather than erase expert inspection.

5. One engine-issued round disposition—without a finding ledger

Semantic round progressionConfidence 74%Complexity Medium
Description
Have the engine combine verdict class and its existing trajectory and budget facts into one round disposition: terminal ship, terminal discussion, eligible after fixes, stop non-shrinking, or budget denied. Keep nuanced fix and dispute narration in the caller, but forbid callers from treating spare numerical budget as semantic permission after a terminal verdict.
Basis
direct: the skill and engine currently govern continuation with different signals and neither consumes the other’s authoritative disposition; NEEDS-DISCUSSION is terminal only in caller prose.
Rationale
This removes one layer of stop-policy recomputation without inventing stable identities for free-form findings. It preserves the engine’s finite spend backstop and makes terminal verdict semantics impossible to bypass through a direct caller.
Downsides
A deliberately small policy cannot encode every disputed-versus-acknowledged nuance. The boundary between engine facts and caller judgment must stay explicit.

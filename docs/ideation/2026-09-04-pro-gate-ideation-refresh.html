Grounding Context

Codebase Context

pro-gate is a final-tier pull-request review gate that drives a logged-in ChatGPT Pro web session over the Chrome DevTools Protocol, then routes findings to a coding-agent fixer. The plugin (skill plus relay agent) ships through the HOV marketplace; the runtime (engine, library, daemon, salvage helper, doctor, stats) installs separately as a version-matched archive. The engine is about 4,200 lines of bash, the library about 3,000, the engine test suite about 5,900.

What shipped between the last ideation docs and today. v0.34.0 split ledger durations at slot acquisition and added wall-clock per round. v0.35.0 recovered finished reviews from stale tabs. v0.36.0 introduced review-decision/v1: one typed next action, checked by contract identity on the skill, relay, daemon, and doctor, with a single named product choice as the only prompt. v0.37.0 unified the attempt lifecycle behind one canonical snapshot, added marker-addressed terminal dispositions, and made round history advisory by default. v0.37.2 through v0.38.2 added proof-backed supersession so an old-head or merged review releases capacity without a refund. v0.38.0 made bundle-only input the default. v0.39.1 added --brief, a swappable task body that is deliberately unexposed through the skill and relay. v0.40.0, today, records a closed-enum failure reason on every failed ledger row.

What was closed. The blocking --wait verb with heartbeat and next-action fields (PR #89, issue #88) was closed unmerged on 2026-09-01 because it added a second controller without adding submit, collect, or recover capability. The ChatGPT-web bridge research (PR #79, the rosetta completion contract) was closed as stale once the lifecycle findings had shipped. The connector-isolation branch was superseded by input policy.

What is still open. Issue #109: a current-head, exact-owned conversation that never emits a verdict pins a slot indefinitely. The root cause found was a synthetic WEB:<uuid> placeholder persisted as the marker's authoritative conversation URL, plus a real-id owned-incomplete case. The issue's guidance forbids any terminalizer from age, TTL, repeated missing verdicts, or an absent spinner alone, and blocks the fix on a turn-scoped terminal predicate verified across bounded fresh renders. Four reproductions exist.

Decisions made outside this repo. The per-PR supervisor from the August ideation was built in dotfiles as a bash wrapper, pro-gate-loop.sh (PR #986): CI wait, typed query, closed action table, a fresh fixer per round, a flat four-round cap, a 30-second poll. The dotfiles umbrella #849 named two Pro capacity lanes, enabled the daemon for a measurement week that ends 2026-09-09, shipped the send-to-Pro primitive as --brief, and withdrew the tunnel-based async lane because the GitHub connector already covers that corpus. The operator's standing instruction is to keep this work in plain operational language: agents take a knowable safe next step without asking routine permission, never repeat the same review without new evidence, and merge only after a verified SHIP.

Still binding from the prior docs

Past learnings

Ship the legible core and let the gate decline fragile automation: repeated FIX-FIRST across two or more rounds on one feature is a signal to drop it, and for a credentialed distributable a clear message plus one manual command beats automation. Separate lifecycle, applicability, capacity, and input trust: one canonical attempt snapshot, capacity as a query over proof, exact recovery instead of retry-as-diagnosis, and evidence-gated residuals left open rather than forced into a timeout. An appended prompt contract is cooperative, not enforced. A staged release tag can predate a later fix on the same version.

External context

Review-gate yield has a vocabulary already: Meta's RADAR escalates only high-risk changes to the expensive tier and reports a 35 percent cut in median review wall time; SWE-PRBench puts AI reviewers at 15 to 31 percent detection with 19 to 42 percent false positives; CodeHerder's review-debt dashboards track p50 and p90 latency, reject-loop depth and cap, and first-pass rate; Span names turn yield. Job systems distinguish never-claimed from claimed-then-died orphans with separate clocks (AWS Step Functions), mark dead-letter rows terminal so a sweep stops re-picking them (Cabana issue 23), and run a scheduled finalize-reconciler distinct from a one-time sweep (Canopy). Kubernetes keeps liveness, completion, and orphan detection as three questions. For completion of a chat turn, browser test guidance converges on asserting an explicit completion-state attribute rather than a hidden spinner or a timeout; ChatGPT's own backend carries a per-message status plus an end-turn flag, but the closest prior art on this product, rosetta, rejects end-turn and stream terminators as proof for the preamble-then-resume behavior pro-gate already hit. Large-diff review at scale is chunked (Qwen Code), two-staged (GitLab Duo), or split recursively (Datadog); stacked review can lose the integration reviewer.

6. A size-aware collect timeout, then a structural tier for large diffs Review yield per slot Confidence 65% Complexity Medium

Description
Two steps on the evidence chain idea 1 provides. First, size the collection timeout to the diff. The twenty-minute value that operators, the skill, and the relay copy from nine hint strings is fixed regardless of payload, it is oracle's own default browser timeout, and a quarter of all still-generating rows end at exactly that boundary. Derive a per-size-band collect timeout from clean-outcome rows only, since harvest and timed-out rows are right-censored at the very value being replaced, use a wide percentile with a floor because the largest band has only 25 clean rows, and have the runtime supply the value so the engine's timeout and oracle's are sized together. The timeout says when to check back; it never becomes authority to terminalize a still-generating review from elapsed time, and the confirmed-absent-probe requirement stays mandatory. Second, only if the band over six thousand lines still loses after the window is fixed, trial the cheapest structural option, risk-ordered hunks in a single payload, and after that a two-turn pre-scan issued as one pre-planned protocol at submission, a scoped first turn and a full second turn in one conversation with one final verdict, never a reactive follow-up when a turn lacks a verdict line, with the second turn's capture checked against the same nonce binding the single-turn path enforces. The cook-and-harvest thresholds, set from one July anecdote, are re-derived from idea 1's size view.
Axis
Review yield per slot
Basis
direct: the ledger's 6,000-plus band since 2026-08-17 shows 25 clean, 38 failed, and 40 stuck; the cook-and-harvest rationale at bin/oracle-review.sh:2881-2890 rests on a single 2026-07-09 observation; 101 of 398 exit-9 rows ended at exactly 1,200 seconds, traced to the hard-coded --timeout 20m hint at seven engine sites plus skills/pro-gate/SKILL.md:152 and agents/oracle-reviewer.md:147, and to oracle's documented twenty-minute default browser timeout; the nonce rule at bin/oracle-review.sh:2575 "NONCE OR NOTHING". external: Meta RADAR's risk-stratified escalation and 35 percent wall-time cut; GitLab Duo's two-stage pre-scan; Qwen Code's hunk-aware chunking; the Software Letters critique that stacked review loses the integration reviewer.
Rationale
This is the only size band pro-gate chose to keep spending on rather than refuse, and it is the band with the worst yield. The ladder turns competing proposals into one sequence where the cheap step may make the expensive one unnecessary, and it finally uses the timing split shipped in v0.34 to decide something.
Downsides
A second turn in one conversation is new complexity and tests the nonce binding; it must stay one PR, one conversation, one verdict. Timeouts derived from a few dozen rows can overfit and must be re-checked after more weeks. A longer collect timeout for the biggest diffs lengthens their worst case, so the cap must stay well inside the reservation TTL.
First step
Compute post-slot duration percentiles by diff-size band over clean rows only and compare the largest band's p90 against 1,200 seconds; no code change is needed for this.
Falsifier
If the clean-row p90 for large diffs is at or below 1,200 seconds, the window is not the cause and the first step is dropped.

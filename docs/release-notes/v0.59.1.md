# v0.59.1

## Highlights

- Salvage no longer trims its record of other runs' conversations, so an old rejection can no longer drop off and let that conversation be trusted again.
- A review record that is a symlink now protects its saved conversation from pruning, the same as it already did during housekeeping.

## Upgrade

Update the plugin and runtime together to v0.59.1. Nothing else to do. Rolling back to v0.59.0 is safe; it reads the same files.

## Details

pro-gate keeps `salvage-nonmatching.txt` in its home directory: one line per conversation a run has proven belongs to a different review, so later scans skip it. Since v0.59.0 it also holds a fingerprint line for each revoked conversation claim once that claim is cleaned up, and that line is then the claim's only record.

Two kinds of writer append to that file at the same time, the engine's shell code and the Node salvage helper, and they share no lock. The engine's housekeeping has long refused to trim the file for that reason: a trim that reads the file and renames a shortened copy over it loses any line appended in between. The Node helper still trimmed it, though. Once the file passed 800 lines, every new rejection it recorded cut the file to its newest 500 lines. That dropped older rejections, and it could drop a line another writer appended during the trim. A dropped fingerprint line lets a conversation the run had already rejected be remembered and trusted again. The run-marker check still refuses to accept another run's review, so the effect was a stalled collection, not a wrong result.

The Node helper now only appends, like every other writer. The file grows by roughly 350 lines a month on an active machine.

The Node helper's memo pruning follows a symlink when it reads a run's review record, while the shell's housekeeping refuses to. A symlinked record whose target was missing, or whose target was a current-format record, therefore left that run's claimed conversation open to pruning in Node while housekeeping kept it. Both now treat a symlinked record as one that cannot be read, which protects the conversation. pro-gate never writes these records as symlinks.

## Fixed

- The Node salvage helper trimmed the shared conversation blacklist, which could drop a rejection or a concurrent writer's line.
- Node memo pruning followed a symlinked review record, so it could remove a conversation the shell kept.

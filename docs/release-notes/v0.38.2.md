## Highlights

- Fixed a narrow case where freeing an outdated review's slot could act on the wrong copy of its record and release a slot still owned by current work.
- Cleanup after a review that never submitted now takes the same lock as every other reservation change, so it cannot race a concurrent recovery of the same review.

## Upgrade

Update the plugin and runtime together to v0.38.2. Nothing else to do — the next review picks it up automatically.

## Details

Supersession now commits against the exact head the recovery step validated with GitHub: the compare-and-swap requires the on-disk immutable binding to still carry that head, and an empty or malformed head is refused rather than falling through to the old unchecked comparison. The ledger's supersession proof strings now record the superseded head (`pr-merged:<head>`, `pr-closed:<head>`; `head-moved:<bound>:<current>` is unchanged). That is additive provenance in a field nothing parses.

The not-submitted cleanup unlinks its input binding under the reservation guard, scoped to the unlink only because the guard is not reentrant. Review of this change found that the interleaving it closes requires a same-marker binding rewrite that no production caller performs, since every run mints a fresh marker, so this is defense in depth matching the reservation-guard idiom rather than a fix for an observed slot loss. Closes #134.

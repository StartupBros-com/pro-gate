## Highlights

- You can now point a Pro review at a question of your own — an architecture critique, a migration-risk read, a security-only pass — instead of only the built-in code review.
- Your own brief replaces the reviewer's instructions but keeps the familiar result shape, so findings still come back ranked by severity with a verdict at the end.
- A brief that is missing, empty, or too large is refused immediately, before a review slot is spent.

## Upgrade

Update the plugin and runtime together to v0.39.0. Nothing else to do — existing reviews are unchanged and keep working exactly as before.

## Details

The engine gains `--brief <task-file>`, which substitutes the task body of the prompt while leaving the rest of the run untouched. It composes with an existing target (`--diff` or `--pr`) rather than introducing a target-less lane, because reservations, the round budget, and supersession are all keyed on the change identity.

The brief chooses the question only; the contract footer is always engine-appended and never caller-controlled. That is deliberate rather than conservative: the return path is review-shaped end to end. A capture is accepted only when it carries a `[Pn]` marker and one of `SHIP`, `FIX-FIRST`, or `NEEDS-DISCUSSION`, and the collector bounds its extraction at the terminal verdict line. A brief able to suppress that footer would produce a conversation that never reaches a terminal state and holds its slot until recovery — the stuck-review shape fixed in v0.38.x. So a brief inherits a severity-ranked-analysis contract, which maps onto most analytical work: findings as `[P0]`–`[P3]`, and a verdict that reads as no-blockers, fix-these-first, or needs-a-decision.

Briefs are validated before any state, lock, reservation, or browser work and are capped at 64 KiB; use `--extra-files` for bulk context. `--brief` is rejected on `--status`, `--harvest`, and `--recover`, which replay a stored prompt and would otherwise ignore it silently. The default review path is unchanged and was verified byte-for-byte identical to the previous release's assembled prompt.

# v0.53.0

## Highlights

- A review that keeps finding new problems round after round now stops with a clear reason instead of quietly buying another paid round.
- A finished review that can never become merge approval now says so once, instead of asking you to collect it forever.
- pro-gate watches the review browser's own memory, not just the machine's, so it holds back a review before the browser wedges instead of losing the round to a stall.

## Upgrade

Reviews already running are not interrupted, and the next review picks up the runtime automatically. Two of this release's protections only take effect after the browser service restarts, because an upgrade replaces files on disk without restarting a running browser: the memory sentinel starts with the browser wrapper, and the new unit limits are written only by a full `install.sh` run (never by the hourly auto-update, which always passes `--skip-services`). On a host where `oracle-chrome.service` is already running: wait until `oracle-review.sh --status` shows no review in flight, run `install.sh --version 0.53.0` (without `--skip-services` if you want the unit limits), then `sudo systemctl restart oracle-chrome.service`. Until then `pro-gate-doctor.sh` reports the memory sampler as not running. Reviews and reservations recorded by v0.48.0 through v0.52.0, and by releases before v0.48.0, stay readable after the upgrade: a finished review is reused instead of bought again, and a stuck reservation can still be released when its pull request moves on. 

## Details

Five fixes, each with a regression test that fails on the previous release.

- **A non-converging review stops with a typed reason.** When two consecutive scored rounds fail to shrink the open P0+P1 count, the next query returns `stop-without-new-review` with reason `rounds-not-converging` instead of granting a round or dispatching a fix, and the decision's governor facts now carry the trajectory behind it: rounds scored, the per-round open counts in order, rounds earned, the streak, the grant and the policy mode. The stop fires regardless of round-policy mode, while the numeric grant keeps its advisory default. `PRO_GATE_ROUNDS_CONTINUE=1` lets one more round through, stateless and per-invocation, the same idiom as `PRO_GATE_FORCE_ROUND`. The review prompt now also tells the reviewer to raise a finding whose fix is a policy the owner must set as NEEDS-DISCUSSION with CHOICE lines rather than FIX-FIRST. Evidence: PR #159 (open counts 1,1,1), PR #166 (2,2,4) and PR #199 (1,1,2,1,1,1,2,3,1) each bought a round past the point a human stopped them. Closes #174.
- **An unbindable completed result stops typed instead of collecting forever.** A completed review whose evidence mode can never carry merge proof — a connector-delivered SHIP — reduces to `stop-without-new-review` with reason `result-not-bindable-for-mode` and the marker in the facts, instead of re-issuing `collect-existing-result` indefinitely. Each completed result now reports `bindable` and `evidence_mode`. Connector delivery still drives fix rounds; only the terminal allow is refused, so a final round needs `bundle` or `both`. Closes #147.
- **A caller-supplied diff earns a reclaimable input binding.** A classic `--pr N --diff <patch>` run now installs a `caller-patch` input binding proving repository, PR and commit target with null patch digests, so `--recover` can proof-supersede the reservation once the PR head moves instead of holding a slot for the conversation's whole lifetime. The head is read from GitHub at install time, never from the local checkout, so a stale clone cannot fake a head move. A `caller-patch` SHIP still never becomes merge-eligible. Closes #161.
- **The browser's own memory is measured, not the host's.** A sampler in the browser wrapper reads its cgroup's `memory.current` against `memory.high`/`memory.max` and writes a pressure sentinel after two consecutive samples at or above 85% of the effective limit; `pg_health_gate` then defers the slot with no quota spent while that sentinel is fresh, and the doctor prints it beside the host-memory line. Every read fails open: absent, unreadable or unlimited cgroup files mean no pressure. Knobs: `PRO_GATE_BROWSER_MEM_PRESSURE_PCT`, `PRO_GATE_BROWSER_MEM_SAMPLE_SECS`, `PRO_GATE_BROWSER_MEM_PRESSURE_TTL`, `PRO_GATE_CGROUP_PATH`. Addresses #212 step 2: the doctor reported 21 GB free minutes before the browser's own cgroup crossed its line and wedged.
- **The shipped browser service unit is bounded.** `oracle-chrome.service` now carries `MemoryMax=70%` and `OOMPolicy=continue`, and deliberately no `MemoryHigh`. Upstream systemd recommends `MemoryHigh` as the primary control; this template omits it because the measured throttle starves the renderer's garbage collector and wedges Chrome rather than bounding it, while `OOMPolicy=continue` keeps a scoped per-process kill from stopping the unit or cascading to the review daemon. A fresh install or a manual `install.sh` run without `--skip-services` applies it; the hourly auto-update always passes `--skip-services` and never reconciles the unit, and an operator drop-in still overrides the base unit. Addresses #212 step 3.

Two things the paid review rounds on this release found and fixed before it shipped:

- **Bindings written under a previous contract digest stay readable.** Every release that changes the review-decision contract digest used to make the previous runtime's binding records fail validation, so an unchanged-head query could buy a second paid round for a review it already held and an in-flight reservation lost the binding that proof-backed supersession needs; the v0.48.0 bump had already done this once. Binding records now validate against the current digest or a compiled list of predecessor digests (`PG_REVIEW_DECISION_COMPATIBLE_CONTRACT_DIGESTS`, currently the v0.48.0–v0.52.0 digest and the one before it); decision and effect envelopes stay strict. Rule for future bumps: append the outgoing digest when the contract change was additive, drop a digest when a proof rule changed.
- **The browser memory sentinel measures against the enforced limit.** It now uses the smaller finite of `memory.high` and `memory.max`, so an operator `MemoryHigh` drop-in above the shipped `MemoryMax` cannot hide the line the kernel actually kills at.

Two candidates were verified and refused rather than built: the inline-size admission guard from #212 step 1 (the ledger shows the same diff failing twice under a cgroup throttle and passing after the limit was raised, and `never` mode exists precisely to paste above the inline budget), and folding case in the marker acceptance predicate from #192 (no incident on record, an existing setting already recovers the described stall, and a narrow cross-host collision path is real).

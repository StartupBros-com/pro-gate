# v0.54.0

## Highlights

- A rate-limit notice left behind on an abandoned review tab no longer restarts the account cooldown on every attempt, so a review waits out one cooldown instead of waiting forever.
- A stuck review's recovery handle is no longer thrown away by routine memo housekeeping while its reservation is still held, so it can still be released later.

## Upgrade

Nothing is required. Reviews already running are not interrupted, and the next review picks up the runtime automatically. Reviews, reservations and cooldown records written by earlier releases stay readable. On a host without the `flock` utility (macOS), the new per-fingerprint lock falls open with one note in the log and the atomic record create still prevents a double charge.

## Details

Two fixes, each with regression tests that fail on the previous release.

- **A stale throttle-modal sighting is charged once per horizon, not on every attempt.** Every rate-limit sighting that is not this run's own routes through one gate that fingerprints it (conversation URL plus modal text), records the fingerprint atomically under `throttle.cooldown.seen.d/`, and charges the account cooldown at most once per fingerprint per seven days (`PRO_GATE_THROTTLE_SEEN_TTL`, in milliseconds; capacity `PRO_GATE_THROTTLE_SEEN_MAX`, default 512). A whole scan charges at most one cooldown; a sighting on the run's own conversation always re-arms it; a throttle surface not proven to belong to another run leaves the scan inconclusive (exit 7) rather than confirmed absent, so a rate limit never spends a recovery-miss. Pruning deletes only the record generation it checked, so a concurrent scan's fresh fingerprint survives; per-fingerprint admission and removal are serialized by a kernel advisory lock on a fixed pool of 64 slot files (a crashed holder releases instantly, so no stale-lock state exists); admission checks a record's age, never just its existence, so an expired record that could not be removed is charged rather than suppressing throttles forever. The lock fails open after 250 ms or when the `flock` binary is absent, with the atomic create as the arbiter. A limiter returning on an already-charged tab is suppressed for at most the seven-day horizon; the retire-on-healthy attempt and its constraints are #217. Twelve paid review rounds on PR #215; the remaining residuals and their reasoning are recorded there. Closes #208.
- **A retained reservation's recovery memo survives housekeeping.** The newest-200 memo eviction and the 14-day memo sweep both skip a `conversation-urls/<marker>` memo whose marker still has an in-progress reservation, so a superseded reservation's only recovery handle is not deleted while it is still held. The path overrides `PRO_GATE_HOME`, `PRO_GATE_COOLDOWN_FILE`, `PRO_GATE_COMPLETED_DIR` and `PRO_GATE_RESERVATION_DIR` resolve through one helper with the shell's empty-or-unset fallback, so an empty override cannot defeat the guard. Two mechanisms were tried and pulled on the way (a scoped tab close on supersession, and a `--close --url` primitive); the findings and the daemon-side reaper alternative are in #218. Groundwork for #206 (PR #216).

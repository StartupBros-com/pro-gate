# v0.55.3

## Highlights

- Recovering a review that no longer exists now says "No review remains", instead of wrongly reporting that the browser needs attention.

## Upgrade

Update the plugin and runtime together to v0.55.3. Nothing else to do.

## Details

`--recover` reports one plain state. When a review's reservation is still held after its time limit, recovery skips the short checks and runs a full search for the review. If that search reaches the confirmed-miss limit, the runtime records that no review remains, releases the reservation, and exits with the same status that browser trouble uses. Recovery then reported **Browser needs attention**, which sent agents off to fix a browser that was working fine. This happened on the v0.55.2 pull request on 2026-09-26.

Recovery already read that record before doing any browser work. It now reads it again after a search that ended without a review, so a record written by the search itself reads as **No review remains**. It is settled under the same lock as before. Real browser trouble writes no such record, so it still reports **Browser needs attention**.

A reservation held past its time limit still runs the full search, about 45 minutes, before reaching this answer. This release does not change that cost.

## Fixed

- `--recover` reported a search that proved the review gone as **Browser needs attention** (#228).

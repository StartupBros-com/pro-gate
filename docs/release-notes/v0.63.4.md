## Highlights

- Looking up a pull request's saved review is fast again on machines that have kept thousands of past reviews: about two seconds instead of over a minute.
- Recording a verdict at merge time no longer times out on a busy machine, so pull requests stop getting parked at the last step.
- Which review counts for a pull request is unchanged, including the damaged or unlabelled records that can still block an older approval.

## Upgrade

Update the Pro-gate plugin and its matching runtime. Nothing else to do; saved reviews and budgets are untouched.

## Details

`oracle-review.sh --review-facts` validated every stored review marker, for every pull request and repository, before deciding whether it belonged to the pull request being asked about. That took about ten subprocesses per marker. Against a store of about 2,200 markers, one query took 101 seconds, and the 120-second verdict-recording timeout parked pull-request owners at merge time (#292).

A single read now rules out, in a few `jq` processes, the markers whose full validation could only have skipped them. Those are full-shape markers whose input binding, run-meta sidecar (valid or damaged) and name all point at another target. Every other marker still gets the full per-marker validation. That covers names that are not full-shape, unreadable, symlinked or oversized files, and bytes outside printable ASCII. Any failure in the fast pass falls back to validating every marker. Marker names and attribution remain relevance hints only. A digest-bound input is still the only thing that can exclude a colliding key without a valid sidecar. On a copy of the live store, the same query took 1.8 seconds and returned byte-identical output.

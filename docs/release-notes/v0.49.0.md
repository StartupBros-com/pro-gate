# v0.49.0

## Highlights

- Fixed a rare case where a review that was actually still running could briefly look finished, risking a duplicate paid review of the same change.

## Upgrade

Nothing to do — the next review picks up the fix automatically.

## Details

A momentary hiccup reading a running process's identity (a busy machine skipping a `/proc` read, for example) could make a live, in-progress review look as if it had already ended. That opened two narrow windows: a fresh review could be launched against a change that already had one running, and a background cleanup pass could treat an active review's lock as free. Both checks now require positive proof that a review has actually ended before treating it as such; a failed or inconclusive read is treated the same as "still running," never as "done."

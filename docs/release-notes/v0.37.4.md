## Highlights

- Pre-v0.31 legacy `diff` reservations with no spend column can now be superseded through exact proof.
- The missing spend is filled only when the marker epoch independently matches immutable binding and canonical run metadata.
- Canonical or arbitrary keys with missing spend, and `diff` records with a different marker epoch, remain fail-closed.

## Upgrade

Update the plugin and runtime together to v0.37.4. No manual migration is required. Re-run exact `recover` for an eligible historical marker.

## Details

Version 0.37.3 canonicalized historical reservations whose literal `diff` key still carried the charged spend column introduced in v0.31. Older reservations can have both a literal `diff` key and an empty spend field. Immutable input binding and canonical run metadata still identify the charged attempt, but the reservation itself lacks the third equality v0.37.3 required.

Version 0.37.4 accepts that older shape only when the reservation key is literal `diff`, its spend field is empty, and the marker epoch exactly equals the charged epoch in both immutable binding and canonical run metadata. The reservation lock rechecks the same predicate before atomically writing the canonical key, proven spend, and `superseded` state. Output, creation time, miss streak, slot, model, charge, URL, and optional audit harvest remain intact. Every other missing or mismatched proof stays generating.

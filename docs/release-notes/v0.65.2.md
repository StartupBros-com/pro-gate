## Highlights

- Pro-gate starts again on a Mac's built-in bash (3.2). Since v0.61.1 it failed with a syntax error before doing anything.
- CI now checks every shipped shell script with bash 3.2, so this kind of break is caught before a release.

## Upgrade

Update the Pro-gate plugin and its matching runtime. Nothing else to do.

## Details

The review-facts lookup changed in v0.61.1 used a `case` statement inside a process substitution without the optional leading parenthesis on its patterns. Bash 4 and later accept that; bash 3.2, which is still `/bin/bash` on every Mac, reads the pattern's `)` as the end of the substitution and rejects the whole library. Anything that loaded it stopped at once with `syntax error near unexpected token` (#295). Linux and Homebrew bash were not affected.

The patterns now carry their leading parentheses, which every bash version accepts, and the lookup behaves exactly as before. CI's source check now runs `bash -n` under bash 3.2.57 on every shell script outside the test suites, and fails the pull request if any of them would not parse on a Mac.

Only parsing under bash 3.2 is checked. Running the full runtime on a Mac is still untested on real hardware.

## Highlights

- A review that has finished generating no longer holds a review slot. It stays collectable, but it stops blocking other runs.
- When no slot is free, pro-gate now tells you exactly which review is holding it and the one command that frees it.
- Runs no longer wait the full 40 minutes against an account that is actually idle.

## Upgrade

Nothing to do. Existing reservations keep working and are treated as still-running until pro-gate can prove otherwise, so the change can only free capacity it is sure about.

## What this means in practice

pro-gate reserves a review slot while the Pro model is writing your review, so a second run cannot start on top of it and waste a Pro turn. That reservation used to last until someone collected the review or until a six-hour safety timeout — even after the model had finished writing.

That gap was invisible in the worst way. ChatGPT keeps conversations on its servers indefinitely, so a finished review still looked present on every check, which reset the "is it gone?" counter and kept the slot held. If a throttle had recently reduced pro-gate to a single slot, one uncollected review could block every other run on the machine for hours, while the account itself sat completely idle.

Now a reservation records whether its review is still being written or already finished. Once pro-gate can prove the review is complete — using the same ownership rules it uses before ever showing you a captured review — it releases the slot and keeps the review collectable. Nothing is thrown away: `--status` still lists it, and `--harvest` still returns it for free.

The safety bias runs one way. An unfinished review, an older reservation from a previous version, an answer that cannot be proven to belong to this run, or any ambiguous reading all keep holding the slot. Starting a second Pro turn on a busy account is a worse outcome than waiting, so pro-gate only releases capacity it is certain about.

Waiting is also no longer silent. If every slot is taken, pro-gate prints which reviews hold them, whether each is still running or merely uncollected, and the exact command to collect a finished one. The timeout message now distinguishes "genuinely busy with running reviews" from "held by reviews nobody collected", because only the second is something you can fix in one step.

## Fixed

- A finished but uncollected review held its account slot until the six-hour TTL, starving other runs — most visibly at effective concurrency 1 after a throttle ([#82](https://github.com/StartupBros-com/pro-gate/issues/82)).
- The slot planner reported a scan range rather than true availability, so a run could believe capacity existed, retry against an impossible plan every three seconds, and then report "all slots busy" while the locks were free.
- The wait loop and slot-timeout error named neither the blocking review nor the remedy.

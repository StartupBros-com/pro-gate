## Highlights

- Run durations now separate time spent waiting for a slot from time the model spent writing, so a slow queue no longer reads as a slow review.
- `pro-gate-stats` reports queue and generation percentiles side by side instead of one blended number.
- The round budget now tells you how much wall clock a change has consumed, not just how many rounds it has spent.

## Upgrade

Nothing to do. The existing `secs` field is unchanged and older ledger rows keep working — they simply have no queue or generation figure to report, and the new percentiles are computed from the rows that do.

## What this means in practice

Every finished run appends a line to the ledger, and until now that line carried a single duration: the time from the moment pro-gate started to the moment it settled. That number quietly bundled two very different things. A run that waited thirty-five minutes for a busy account and then generated for ten looked identical to one that started immediately and spent forty-five minutes thinking.

That mattered because the blended figure was the only evidence available for the question people actually ask: is the gate slow, or is the queue full? Those have opposite remedies. A slow queue is a capacity problem; a slow review is a model-latency problem, and no amount of added concurrency fixes it.

A run now records both halves. The split is stamped at the moment the run acquires its slot and generation is about to begin — never when the run was first identified, which on a queued run can precede the real charge by a long wait. A run that never reaches that point, because it timed out waiting for a lock or failed its preflight, records its whole life as queue time and no generation time. A collection pass records its own short wall time, because it reads a conversation the model already finished rather than generating anything.

The round budget gained the same kind of honesty. Each recorded round now carries how long it took, and `--status` and the round-cap refusal report the total alongside the round count. The total names its own scope: it reads "3 rounds; ~1.4h recorded across 2 scored round(s)" rather than implying every charged round contributed. A round that was charged but never produced a review — a lost generation, or one nobody collected — is counted in the first number and cannot appear in the second, and the wording no longer hides that gap.

The duration is deliberately described as recorded time rather than generation time. On a collection pass it spans from the original charge to whenever someone ran the collection, so it includes however long a finished review sat waiting to be picked up. That is useful for judging what a change has cost, but it is not a measurement of how long the model took, and the field says so rather than implying a precision it does not have.

## Fixed

- Duration percentiles blended queue wait with generation time, so neither could be read on its own.
- A backward clock adjustment between the timestamps a run samples could write a negative duration into the ledger and into the percentile sort.
- The round-cap refusal paired a count of every charged round with hours drawn only from rounds that recorded a result, without naming the difference.

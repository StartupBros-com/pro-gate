## Highlights

- Reviews now track the pull request's actual target branch, even when your feature branch tracks itself or your checkout is shallow.
- A moved or retargeted pull request stops a stale review request before another review is submitted or charged.
- Existing review records stay available for recovery; missing target-branch proof never silently buys a replacement review.

## Upgrade

Update the plugin and runtime to the same version through the normal promotion path. No browser restart or account change is required for this fix.

Custom callers using typed review decisions must first adopt `--prepare-review-evidence` and pass both `PRO_GATE_REVIEW_ENDPOINT_PATCH` and `PRO_GATE_REVIEW_PR_EVIDENCE` through query and effect. The bundled skill, relay, and daemon include this integration. Separately installed wrappers need their matching caller update; do not deploy this runtime ahead of that update.

Historical full/scoped reviews without authoritative PR metadata remain recoverable by exact marker, but cannot establish current merge eligibility or automatically authorize a replacement at the same head. Preserve the original records rather than editing them to pass a check.

## Details

The runtime reads GitHub PR metadata before and after fetching the endpoint patch, recording the repository, PR number, head, base tip, and base ref. Queries read this prepared evidence locally. Guarded effects revalidate the authoritative metadata before charge or result-binding repair. Final handoff requires freshly prepared evidence; a file-only advisory query is not a live GitHub check.

The daemon also invalidates cached completion when the PR is retargeted to another branch at the same base commit. This fixes PR evidence identity, not Oracle attachment delivery, browser memory pressure, or ambiguous submission recovery.

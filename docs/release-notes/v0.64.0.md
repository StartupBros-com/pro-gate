## Highlights

- A finished answer that fails review checks now stops cleanly with a clear reason, instead of leaving the review stuck in recovery forever.
- The refused answer is kept exactly as written, so you can read what the model said without another review being spent.

## Upgrade

Update the Pro-gate plugin and allow its normal runtime update to complete. Nothing else is required; stopped reviews are not restarted by the upgrade.

## Details

Before this release, a harvest that refused a completed, current answer kept every recovery handle and reported the review as still recoverable. A verdict skeleton without a grounded diff reference (exit 6), or a complete review without the run-marker echo (exit 9), could therefore be harvested again indefinitely, with each pass refusing the same bytes. The refusal rules are unchanged: those answers are still never accepted, and the charge, reservation and input binding are kept.

What changes is the evidence the harvest keeps. The browser helper now reports a completion proof only when the bytes it printed are the finished last assistant response after this attempt's marked prompt: no generation running, the finished-turn actions present, identical text on a re-read about 2.5 seconds later, and the same conversation URL as the attempt's memo and any matched source the helper recorded. When the harvest then refuses those bytes, it writes one write-once record (mode 0600) at `$PRO_GATE_HOME/rejected-captures/<marker>`. The record binds the exact bytes and their SHA-256 to the marker, charged epoch, input binding and conversation URL, and is written only after the existing set-aside copy of the refused bytes exists. A record that cannot be written is reported as an error and leaves recovery state unchanged.

The next typed `--review-decision` returns `stop-without-new-review` with reason `rejected-capture`, execution class `report-only`, and the normal exit 0. Its `.facts.completed_results` row has `shape:"rejected-capture"`, `applicable:false`, `verdict:"NONE"` and the capture digest. The stop applies only while no other attempt is active and no other attempt holds the reservation. A newer applicable completion supersedes it, and other live work still routes to recovery. A damaged, truncated, foreign or tampered record reads as absent, which keeps today's recovery path.

The stop never resumes the attempt. A later vocabulary or classifier repair leaves it stopped, and the record is never rewritten. An explicit `--harvest` may reinspect the conversation; if it collects an accepted result, that result drives the next decision. A generating, unfinished, foreign or stale response, a changed re-read, or a response that is not the last assistant turn after the marked prompt produces no proof and keeps the existing recovery behaviour.

The review-decision contract gains the `rejected-capture` reason and shape, so its digest changes. Bindings written under the previous contract stay readable through the compatible-digest list. Fixes #271.

## Highlights

- Fixed a crash in the browser cleanup and pre-flight steps that printed a raw error and left stale review state behind.
- A stuck review is now cleared by those same cleanup runs, so the status output stops advising you about a review that already finished.
- Release announcements are now tied to the exact release they describe, so a captured credential cannot announce a version that was never published.

## Upgrade

Nothing to do beyond your usual update. If the doctor reports that the runtime and the plugin
are on different versions, it prints the exact command to bring them back in line.

## What this means in practice

The cleanup and pre-flight steps that tidy up leftover browser tabs were exiting through an
error before they could finish their bookkeeping. Two things followed from that. You saw a
raw error trace during an otherwise healthy pre-flight, which reads like a broken install.
And the note that marks a review as genuinely stuck was never cleared by those runs, so
`--status` could keep telling you to look at a review that had already sorted itself out.

Both are fixed, and the fix is checked by asserting the bookkeeping actually happened rather
than that the command merely exited quietly — which is how the original problem hid inside a
passing test suite for so long.

Separately, pro-gate's own release announcements now prove which release they belong to. The
announcement is bound to the published release's identity, so an announcement cannot be
produced for a version that was never released.

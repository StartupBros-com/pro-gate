## Highlights

- You can now point a Pro review at a question of your own — an architecture critique, a migration-risk read, a security-only pass — instead of only the built-in code review.
- Your own brief replaces the reviewer's instructions but keeps the familiar result shape, so findings still come back ranked by severity with a verdict at the end.
- A brief that is missing, empty, too large, or aimed at a pull request is refused immediately, before a review slot is spent.

## Upgrade

Update the plugin and runtime together to v0.39.0. Nothing else to do — existing reviews are unchanged and keep working exactly as before.

## Details

The engine gains `--brief <task-file>`, which substitutes the task body of the prompt while leaving the rest of the run untouched. It requires `--diff` and is refused together with `--pr`: round budget, the per-change guard, supersession and recovery are all keyed on change identity, so a brief sharing a pull request's identity would spend that PR's rounds, serialize against the real review, and could be returned by recovery in place of it. Brief runs always take a diff-derived identity of their own.

The engine appends its own contract footer, because the return path is review-shaped end to end: a capture is accepted only when it carries a `[Pn]` marker and one of `SHIP`, `FIX-FIRST`, or `NEEDS-DISCUSSION`, and the collector bounds its extraction at the terminal verdict line. An answer lacking that shape is discarded and holds its slot until recovery — the stuck-review shape fixed in v0.38.x. So a brief inherits a severity-ranked-analysis contract: findings as `[P0]`–`[P3]`, and a verdict reading as no-blockers, fix-these-first, or needs-a-decision. The footer also pins the run to a single turn and directs the model to state assumptions rather than ask a clarifying question, since a completed turn that asks a question carries no verdict and would hold its slot.

That footer is a cooperative contract, not an enforced one: brief text and footer carry equal authority, so a brief can dictate its own verdict. This is safe because briefs are operator-authored and no typed decision path consumes a brief run's verdict — `--brief` is deliberately not exposed through the skill or the relay agent, and that non-exposure is a security boundary rather than a scoping preference.

Briefs are validated before any state, lock, reservation, or browser work and are capped at 64 KiB; use `--extra-files` for bulk context. `--brief` is rejected on `--status`, `--harvest`, and `--recover`, which replay a stored prompt and would otherwise ignore it silently. Note that any run without `--pr`, brief or not, cannot write recovery metadata and so has degraded repository-qualified recovery; harvest by exact marker still works. The default review path is unchanged and was verified byte-for-byte identical to the previous release's assembled prompt.

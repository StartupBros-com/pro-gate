## Highlights

- pro-gate now carries one small checked identity record with the runtime and plugin, so a mismatched adapter stops before it can start a review.
- The runtime gives one safe next step when it can prove one. It does not add routine permission prompts or repeat a review with identical evidence.
- Recovery stays first: collect or recover existing work before considering another Pro review.

## Upgrade

Update the plugin and runtime together to v0.36.0. If pro-gate reports an identity mismatch, use its exact version-update path; it will not guess or fall back to a fresh review.

## Details

The packaged runtime now includes the review-decision contract ID, version, contract digest, and conformance-corpus digest. The installer checks the compact metadata against the staged library before changing a live runtime, preserves the previous runtime on checksum, extraction, or identity failure, and writes the deploy stamp last.

The Claude skill, Oracle relay, doctor, and daemon compare the same identity in a clear direction. Runtime-newer, adapter-newer, unknown-contract, contract-digest, corpus, missing, and malformed states all stop through the existing update path. A later compatible deployment reloads normally.

This release keeps the product boundary unchanged: pro-gate chooses safe review continuation, recovery, collection, stopping, and merge eligibility handoff. Coding agents keep code-edit authority, and the existing surrounding workflow remains the only merge authority.

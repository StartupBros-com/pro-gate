# v0.42.0

## Highlights

- A review that remembered a fake conversation address can no longer hold a ChatGPT slot for days; the bad memo is dropped and the run clears through the normal absence checks.
- Status now says what kind of stall an unresolved review is in, and how long until its hold expires, instead of "in progress" for everything.
- Nothing about when a review is declared finished, refunded, or released has changed.

## Upgrade

Update the plugin and runtime together to v0.42.0. Nothing else to do. Any placeholder memos already on disk are cleared by the next collection pass or reconcile probe for their marker; you do not need to delete anything by hand.

## Details

Since late August a handful of reviews reported "Still working" for a day or more while holding one of the account's review slots. Each had remembered a synthetic address of the form `https://chatgpt.com/c/WEB:<uuid>` as its conversation. That page is not a conversation, so every collection pass rendered it, found neither the run's marker nor anyone else's, and treated the result as a transient rendering failure, which by design never counts against the review. The run was parked indefinitely. The existing check on remembered addresses looked only at the `https://chatgpt.com/c/` prefix, so the placeholder passed it.

The browser helper now checks the conversation id itself, both when it remembers an address and every time it reads one back. The id must be a single path segment of letters, digits, and dashes; every real id on the operator's machine passes and the placeholder's colon fails, including a placeholder whose body happens to be a well-formed UUID. A memo that fails is revoked in the same pass, using the same claim-then-verify removal that already protects against a concurrently republished genuine memo, and the pass rescans its candidates. With nothing carrying the marker, the pass reaches the ordinary confirmed-absent path: one miss per probe, release only after the reservation window and the miss threshold are both met, charged round retained. A real conversation whose page renders blank is still treated as a transient and stays held, exactly as before.

Every collection pass and reconcile probe now records one word for what the helper concluded, in a small per-marker file. Status reads it and reports `classification`, `classified_at`, and `ttl_remaining_secs` beside the age and miss fields it already carried, in both the human and JSON forms. The human line words each class plainly and gives the next step that fits it: a throttled account says back off, an unreachable browser says check Chrome first, and a probe that found only another run's answer says run the harvest so the conviction is recorded. The recovery relay's six state lines are unchanged.

## Fixed

- A placeholder conversation memo parked its run indefinitely because a blank render never counts as a miss.
- Status could not distinguish a parked run from one whose model was still writing.

## Highlights

- Fixed a rare case where a finished review could get stuck and block that pull request from being reviewed again until someone intervened by hand.
- A review that cannot be matched to your pull request is now always set aside rather than returned, so you never receive findings that belong to a different change.
- Stuck reviews now clear themselves, and the status output tells you whether to simply retry or whether something needs a look.

## Upgrade

Nothing to do. If a pull request is currently stuck waiting on a review, it will clear on
its own within a few hours.

## What this means in practice

When several reviews run at once, pro-gate occasionally attached the wrong conversation to
a pull request. It correctly refused to return that mismatched review — the safety check
worked — but the bad association was remembered, so every retry hit the same wall and the
pull request could not be reviewed again. One review was lost to this before we caught it.

pro-gate now decides which conversation belongs to your change by looking at the finished
answer rather than a surface match, discards a bad association as soon as it proves one,
and lets a stuck review expire on its own. `--status` now distinguishes "retry this, it may
just still be running" from "this one is genuinely stuck", so you are not guessing.

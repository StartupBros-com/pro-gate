# v0.44.0

## Highlights

- Fixed a rare case where a review could come back carrying a second, unrelated review — findings about files that are not in your repository at all.
- A review that arrives mixed with another one is now trimmed to your own result, or refused outright; it is never handed to you or to a fixer.
- The reverse case is fixed too: a result that used to be thrown away, costing you the whole round, is now collected normally.

## Upgrade

Update the plugin and runtime together to v0.44.0. Nothing else to do — the next review picks it up automatically.

## Details

Each review prompt asks the model to sign its `VERDICT:` line with the run's own marker, and the engine accepts a result only when that signature is present. It checked the end of the answer, which is the wrong place to look when one ChatGPT conversation has received two different runs' prompts and the model has answered both: the page then holds two complete blocks, each signed by a different run. When ours happened to be last, the whole page passed the check and was published. The caller reads the first `VERDICT:` line it finds, so it acted on the other run's verdict and sent a fixer at a path from another repository — and the round was spent without this repository's own result ever being counted.

Collection now works on the block closed by this run's own signature rather than on whatever verdict sits last:

- The answer is cut to that block before anything is published, in both the browser collector and the engine, so a result reaching the caller through any path carries one run's findings.
- If another run's signature would survive that cut, the capture is refused rather than published. It is set aside intact for inspection, the reservation is kept, and the round stays recoverable.
- The mirror-image layout — this run's block first, another run's after it — used to make the collector disown the whole conversation, discarding a finished review and losing the round with it. A page carrying this run's own signed verdict is no longer treated as somebody else's.
- A clean single-answer capture is passed through byte for byte, exactly as before.

The route in is narrowed as well. The Oracle session was named after the pull request, so every round and retry of one PR competed for the same name and was disambiguated with a numeric suffix — a name a later invocation could mint or attach to just as easily. It is now pinned to the run marker, which is unique to a single invocation.

## Fixed

- A completed review could be published carrying another run's review block, including its verdict line and findings (#164).
- A completed review followed by another run's answer in the same conversation was discarded instead of collected, spending the round for nothing (#164).

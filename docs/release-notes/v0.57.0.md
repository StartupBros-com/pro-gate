# v0.57.0

## Highlights

- A review waiting for a free slot now releases slots still held by pull requests that have merged, closed or moved on, so it no longer waits behind them for hours.
- A finished review whose conversation later disappears no longer starts holding a review slot again.
- When Oracle exits by itself, pro-gate collects at once instead of waiting up to 10 seconds, and no longer reports that run as killed by its watchdog.

## Upgrade

Update the plugin and runtime together to v0.57.0. Nothing else to do. Rolling back is safe: an older runtime reads the released reservations the same way.

## Details

A review slot belongs to a reservation: a record that a run has spent on the ChatGPT account and may still be using it. A run that stops before its review comes back keeps its reservation, so the account is not overbooked while ChatGPT is still working on it. When the pull request that reservation was for has merged, closed or moved to a new commit, the review no longer applies. Since v0.37.2 pro-gate could prove that and release the slot, but only when someone ran `--recover` on that exact run. Nothing did it on its own.

On 2026-09-27 that left four failed sends from three sessions holding all four slots, two of them for pull requests that had already merged. A third session's review sat in the slot queue behind them until someone ran `--recover` by hand.

Now, when a fresh run finds no free slot, it runs the same proof on each finished run still holding a slot:

- the run's own immutable record of the pull request and commit it reviewed;
- its charge record, which must name the same repository, pull request and charge;
- one bounded GitHub read of the pull request's state and current head.

If the pull request merged or closed, or its head moved past the reviewed commit, the reservation stops holding a slot and the waiting run takes it in the same run. The round stays charged. The ledger records the same `superseded` event `--recover` writes, and the old review can still be collected for audit.

Anything unproven leaves the slot held: a missing or mismatched record, a GitHub read that fails or times out, or a pull request still open at the reviewed commit. The GitHub read happens while no reservation lock is held. A run that gets a slot straight away makes no GitHub call for other runs. A waiting run checks at most once per `PRO_GATE_RECONCILE_INTERVAL` (60 seconds by default) and starts no check after its wait's deadline. When a check that started in time frees a slot after the deadline, the run still takes that slot. The slot-wait report still names `--recover` for a holder whose GitHub state could not be read.

Two related record fixes:

- The pre-dispatch sweep re-reads a reservation's state before it rewrites the record after a browser probe. A release proven during that probe, which can take ten seconds, is no longer turned back into a held slot.
- A confirmed probe miss keeps the reservation's lifecycle state, and so does the live probe that later clears that miss. Before, a finished review that holds no slot started holding one again after its conversation stopped showing up, until three spaced misses and the six-hour limit released it.

The watchdog that watches a running Oracle checked it only once every 10 seconds. A run that ended on its own could wait out the rest of that interval before capture and salvage started. It now waits in 1-second steps and stops as soon as Oracle exits. Its stall and no-think checks keep the 10-second cadence while Oracle is running, and never run once Oracle has exited. Before, one last check after the exit could label an Oracle that stopped by itself as watchdog-killed and discard the transcript that proves what it sent. The test suite paid the same wait on every run: CI's test step fell from 41m28s to 31m22s, back under its 45-minute limit with room to spare.

## Fixed

- A merged, closed or moved-on pull request's stalled run held a review slot until someone ran `--recover` on it (#234).
- A dispatch sweep's live probe could undo a release proven while it ran (#234).
- A confirmed probe miss erased a finished review's state and re-armed its slot (#236).
- A finished Oracle waited up to 10 seconds for the watchdog's next check, and one last check after it exited could label it watchdog-killed and discard its transcript proof (#233, PR #237).

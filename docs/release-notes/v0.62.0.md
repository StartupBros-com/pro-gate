## Highlights

- A bare verdict skeleton no longer counts as a completed review: Pro-gate requires a reference to the reviewed change before reporting success.

## Upgrade

Update the Pro-gate plugin and allow its normal runtime update to complete. Consumers can version-gate the new outcome and ledger fields on v0.62.0.

## Details

Reviews that name no path or shaped identifier from the reviewed diff fail with exit 6 and the typed outcome `template-verdict`. The prompt now requires a clean review to include a short rationale paragraph, separate from severity labels and the final verdict, citing a changed path, file:line, or identifier and naming what was checked. A VERSION-only or docs-only change is cited by its path. Severity labels cannot establish a match; a diff reference in the reason after the verdict word can. Plain English words still cannot establish a match. A compact token index preserves the reviewed payload's vocabulary for later collection without another network fetch.

The same read-only, marker-based shape check now guards saved-result recovery, typed decisions, public review facts, binding repair, and legacy daemon completion. Unflagged historical skeletons cannot supply accepted facts or completion evidence. Saved results without retained diff vocabulary or a legacy path manifest are rejected as `template-verdict`; their stored bytes remain available for inspection.

A typed query for a saved skeleton now returns a complete `stop-without-new-review` decision with reason `template-verdict`, the rejected marker and artifact digest in its facts, and the normal typed-query exit 0. A newer grounded review at the same head supersedes an older skeleton; a newest skeleton still stops closed. This additive contract update preserves reads of predecessor binding records. Recovery and other legacy entry points keep exit 6.

Removed identifiers are recognized without the unified-diff deletion prefix. Identifiers in the trailing function context of a hunk header also count; hunk ranges and headers without context contribute none. Other diff metadata contributes paths rather than header markers. A skeleton capture followed by a browser outage that defers recovery with exit 9 keeps its `in-progress` outcome and does not teach the ramp a failure. Only a final exit 6 can receive the legacy `template-verdict` outcome.

The browser harvester keeps waiting within its existing budget when the answer contains only a verdict block. Every run ledger row includes `body_bytes` and the boolean `names_nothing`; existing fields remain available. Fixes #262.

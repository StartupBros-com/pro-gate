## Highlights

- Reviews that cite changed files using line ranges no longer get rejected as empty templates.
- Rejected review text is now kept for inspection instead of disappearing after collection.

## Upgrade

The fix applies after the plugin and runtime update together. Existing stopped reviews remain stopped; this release does not reset review limits or approve saved answers automatically.

## Details

The grounded-review check now recognizes citations such as `file.ts:22-40`, including full paths and identifiers with line ranges. The cited name must still match the retained reviewed input exactly. Unknown names, partial identifier matches, and references appearing only on the verdict line remain insufficient.

Rejected bytes are retained separately from accepted review artifacts, including when the caller uses the default output location. This fixes the line-range false rejection observed during #271 without changing nonce checks, attempt dispositions, charges, or recovery policy. Other marker-format and delivery cases in that issue remain open.

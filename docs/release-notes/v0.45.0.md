# v0.45.0

## Highlights

- A pull request is recorded as reviewed only when a review actually finished, so one can no longer be skipped forever without ever being looked at.
- Reviews wait for the pull request's checks to settle first, instead of starting against a result that has not arrived.
- A pull request that exhausts its retries is now marked blocked and stays visible, rather than quietly counting as done.
- Saved review material is kept private to your user account and is cleaned up when it is no longer needed.
- Records from earlier versions that cannot be proved are set aside for a fresh look instead of being trusted.

## Upgrade

Update the plugin and runtime together to v0.45.0. Nothing else to do.

On first start after upgrading, the daemon moves its completion records to a new file and re-checks the old ones. Any earlier record it cannot back with real review evidence is set aside, and those pull requests are simply looked at again. Expect a small burst of re-examined work on the first run; nothing is deleted, and the previous file is left untouched.

## Details

The daemon keeps a record of which pull request revisions it has finished, and skips anything already in it. Several paths could add a revision to that record without a review ever having completed — and because the record is permanent, the pull request was then skipped forever while still carrying the label that tells everything else it already has an owner.

This was observed in practice, not just in review: a dependency pull request was handed to the daemon, an internal task exited successfully without producing a review, and the revision was recorded as finished with no review artifact anywhere.

- **Only a finished review completes a revision.** A single guarded function is now the one place that writes the completion record, and it accepts only a current-revision review result or a matching prior one. A helper task finishing, a worker exiting cleanly without submitting, and a run giving up after repeated failures are each handled on their own terms and none of them records a revision as reviewed.
- **Checks must settle before a review starts.** A revision whose checks are still queued, waiting, requested or expected is left alone until they finish. A repository with no checks at all is configured explicitly rather than inferred from an empty result, because "no checks yet" and "no checks ever" look identical for the first few seconds after a push.
- **Giving up is visible.** When a revision hits a retry limit it is written to a separate blocked record and reported, so it can be found and dealt with. It is never mixed into the completed record. A new push clears it.
- **Review material is private and temporary.** The saved copy of a pull request's changes is written readable only by your own user account, and is removed once the revision is finished or superseded. Abandoned copies are swept after a grace period so they cannot accumulate.
- **Old records are re-checked, not assumed.** Each record from a previous version is matched against real review evidence for that exact repository, pull request and revision before being carried forward. Anything unproven is set aside for a fresh look.

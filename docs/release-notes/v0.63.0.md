## Highlights

- Reviews with only minor findings now hand off to your existing merge workflow and preserve those findings for follow-up.
- The default review grant is now two rounds, while explicit limits and earned rounds remain available.

## Upgrade

Update the Pro-gate plugin and allow its normal runtime update to complete. Existing saved reviews remain readable; no migration is needed. Explicit round settings retain their behavior.

## Details

An accepted current FIX-FIRST with zero open P0 and zero open P1 now emits `allow-existing-merge-workflow` with reason `fix-first-deferred-p2-only`. The decision includes `facts.open_blocking: 0`, an ordered `facts.deferred_findings` array of `{severity: "P2"|"P3", text: "finding line without its list marker and severity label"}`, and `facts.deferred_count`. Status-position RESOLVED P0/P1 findings do not count as open. An open P0/P1 still requires a fix, and the `rounds-not-converging` stop retains precedence.

The advisory `PRO_GATE_ROUNDS_BASE` default changes from 3 to 2 to match the reduced round budget. Invalid `PRO_GATE_MAX_ROUNDS_PER_PR` values now fall back to 2 instead of 4; an explicit valid cap such as 4 still works. Shrinking review trajectories still earn rounds up to the unchanged ceiling of 8. Unset round settings remain advisory.

Pro-gate reports the deferred findings; filing follow-up issues belongs to the surrounding workflow. This release does not merge a PR or bypass repository checks. The predeclared countermetric counts deferred findings later fixed as real bugs among decisions with this reason, with a review after 30 days of data. Fixes [#274](https://github.com/StartupBros-com/pro-gate/issues/274).

## Highlights

- Reviews with only minor findings now hand off to your existing merge workflow and preserve those findings for follow-up.
- The default review grant is now two rounds, while explicit limits and earned rounds remain available.

## Upgrade

Update the Pro-gate plugin and allow its normal runtime update to complete. Existing saved reviews remain readable; no migration is needed. Explicit round settings retain their behavior.

## Details

An accepted current FIX-FIRST with proven zero open P0 and zero open P1 and at least one deferred P2/P3 now emits `allow-existing-merge-workflow` with reason `fix-first-deferred-p2-only`. The decision includes `facts.open_blocking: 0`, an ordered `facts.deferred_findings` array of `{severity: "P2"|"P3", text: "complete finding block without its leading list marker and severity label"}`, and `facts.deferred_count`, equal to the array length. Finding text retains continuation lines, evidence, confidence, suggested fixes and code blocks. Each text is limited to 1,024 characters, including a `… [truncated N chars]` marker when needed, so a long finding still permits the decision.

Severity parsing accepts bullet and numbered lists, bracketed and bare labels, bold or underscore markup, optional colons and lower case. An unrecognized P0/P1 headline leaves counts unavailable and keeps `fix-review-findings`; explicit `P1: none` declarations still prove zero. Status-position RESOLVED P0/P1 findings count as closed only when their whole block contains no later reopening: `STILL-PRESENT`, `REOPENED`, `NOT RESOLVED`, `NOT FIXED` or `Correction:` in a continuation makes the finding open. An open P0/P1 still requires a fix, and the `rounds-not-converging` stop retains precedence.

A FIX-FIRST body with zero open blockers and zero deferred findings contradicts its verdict. It emits `fix-review-findings` with reason `fix-first-without-findings` so the loop re-reviews instead of handing off to merge. The daemon recognizes the valid deferral allow as completion of the current head, avoiding repeated polls of an unchanged reviewed revision.

The advisory `PRO_GATE_ROUNDS_BASE` default changes from 3 to 2 to match the reduced round budget. The status heading derives its default base from the scorer and reports 2 with settings unset. Invalid `PRO_GATE_MAX_ROUNDS_PER_PR` values now fall back to 2 instead of 4; an explicit valid cap such as 4 still works. Shrinking review trajectories still earn rounds up to the unchanged ceiling of 8. Unset round settings remain advisory.

Pro-gate reports the deferred findings; filing follow-up issues belongs to the surrounding workflow. This release does not merge a PR or bypass repository checks. The predeclared countermetric counts deferred findings later fixed as real bugs among decisions with this reason, with a review after 30 days of data. Fixes [#274](https://github.com/StartupBros-com/pro-gate/issues/274).

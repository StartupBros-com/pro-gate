## Highlights

- Old-head and merged/closed PR reviews no longer occupy shared ChatGPT account capacity indefinitely.
- Superseded reviews keep their charged round, exact marker, conversation URL, and optional audit harvest.
- Current-head typed admission ignores superseded ownership without manual deletion or force flags.

## Upgrade

Update the plugin and runtime together to v0.37.2. Existing reviews need no state migration. Running exact `recover` on an eligible marker performs the proof-backed transition automatically.

## Details

A review can remain readable or appear incomplete after its target PR has moved, merged, or closed. Earlier releases conservatively kept that reservation recoverable, which was correct for ambiguous browser state but allowed permanently irrelevant work to consume local account-capacity accounting.

Version 0.37.2 adds one monotonic reservation state: `superseded`. Exact recovery reads the marker's validated immutable input binding, then performs a bounded GitHub read. A `MERGED`/`CLOSED` PR or current head different from the bound head is sufficient proof. Missing, malformed, or unavailable binding/GitHub evidence changes nothing and ordinary recovery stays fail-closed.

Supersession never refunds or deletes the original attempt. It retains marker-addressed state for optional audit harvest, records the proof in the ledger, reports `holds_capacity=false`, and cannot be re-armed by later harvest/live/miss bookkeeping. The typed lifecycle treats the old review as non-applicable and permits a replacement review only for current evidence.

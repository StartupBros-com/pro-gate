# v0.48.0

## Highlights

- A review that hits ChatGPT's rate limit now recognises it and waits, instead of reading the limit notice as an answer still being written.
- While that wait is in effect, pro-gate says how much longer it will refuse to start a new review, so a quiet run is distinguishable from a stuck one.
- Nothing about when a review is declared finished, refunded, or released has changed.

## Upgrade

Update the plugin and runtime together to v0.48.0. Nothing else to do.

## Details

When ChatGPT rate-limits an account, it covers the conversation with a notice rather than closing it. The page underneath is still the real review, still carrying this run's correlation id, so every check that asked "is our conversation here and still working?" answered yes. The run kept waiting on an answer that could not arrive, and each further check was another page load against an account that was already being limited.

- **The limit notice is now its own state.** A conversation sitting under the rate-limit notice is reported as throttled rather than as still-generating. The run stops waiting on it, starts the account back-off, and does not resubmit. This is a deferral, not a failure: nothing is charged, and the pull request stays due for review rather than being recorded as finished or given up on.
- **The remaining wait is a stated fact, not a guess.** How long the back-off has left is now part of the decision pro-gate hands back, so anything built on top — the daemon, a wrapper, a script — can wait it out instead of asking again and being refused. The daemon reports it in the same line that explains why it did not start a review.
- **Back-off applies before the next page load, not after.** Because every check is itself a request against the limited account, the cooldown is consulted per conversation during reconciliation rather than once per sweep. A limit discovered while checking one review is respected by the checks that follow it in the same pass.

An account already in back-off behaves as it did before: the review is deferred, the run exits with the existing deferred status, and no slot is spent.

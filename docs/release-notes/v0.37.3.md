## Highlights

- Historical reservations keyed as literal `diff` can now enter proof-backed supersession without manual state repair.
- The exact transition canonicalizes that one legacy key while preserving every recovery field and the charged round.
- Status JSON now keeps empty model fields empty instead of absorbing spend and lifecycle columns.

## Upgrade

Update the plugin and runtime together to v0.37.3. No manual migration is required. Re-run exact `recover` for an eligible historical marker; arbitrary key mismatches remain fail-closed.

## Details

Version 0.37.2 added the monotonic non-capacity `superseded` state. Historical harvest fallback could, however, persist a reservation under literal key `diff` while immutable input binding and canonical run metadata retained the exact repository/PR key. The v0.37.2 proof gate correctly refused that mismatch, but the old marker could not release obsolete capacity through the supported path.

Version 0.37.3 accepts only the already-canonical key or literal legacy `diff` after exact marker, immutable binding, canonical run metadata, charged epoch, and GitHub supersession proof all agree. One reservation-guarded transition rewrites `diff` to the canonical key and sets `superseded`, preserving output, creation time, miss streak, slot, model, spend, URL, charge, and optional harvest. Every other mismatched key remains generating and no GitHub query is trusted for it.

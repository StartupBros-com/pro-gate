## Highlights

- One attempt lifecycle now keeps status, recovery, and fresh-review decisions consistent after browser transport failures.
- Proven pre-send failures refund; terminal ChatGPT errors and exhausted recovery release the change without refund.
- Round history is advisory by default; explicit caps and lockdown remain available.

## Upgrade

Update the plugin and runtime together to v0.37.0. Existing active runs, reservations, artifacts, bindings, round history, and run metadata remain readable; no state migration or manual cleanup is required.

If your `.env` explicitly sets `PRO_GATE_ROUND_GUARD`, `PRO_GATE_MAX_ROUNDS_PER_PR`, `PRO_GATE_ROUNDS_BASE`, or `PRO_GATE_ROUNDS_CEILING`, that explicit enforcement remains in effect. Leave those unset for advisory round history.

## Details

Pro-gate cannot observe the ChatGPT subscription's remaining chat capacity. Earlier releases used a local per-change round count as a hard default proxy, which could leave usable capacity idle after infrastructure failures. Version 0.37.0 separates safety from advice: active or recoverable work, identical code and evidence, invalid provenance, throttle, browser health, concurrency, and payload limits still block unsafe submission; round count and churn do not block unless explicitly configured.

A new marker-addressed terminal disposition preserves proof that a run never submitted, ended in an exact-owned ChatGPT infrastructure error, or exhausted bounded recovery. Status, typed decisions, effect freshness, and recovery consume the same canonical snapshot. Terminal cleanup is idempotent and completes before another charge. Valid late review bytes still win.

Oracle 0.18.0 session metadata is now the authority for pre-send refund proof. Missing, conflicting, post-click, or watchdog-interrupted evidence stays charged and fail-closed. Recovery exhaustion requires the existing TTL plus confirmed exact-marker misses; elapsed time alone never releases a possibly live review.

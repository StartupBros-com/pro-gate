# v0.55.2

## Highlights

- A pull request whose earlier review round never produced a review can be reviewed again at the same commit, instead of staying stuck until a new commit is pushed.
- A review search that ends right at its time limit reports what it found, instead of sometimes reporting the browser as down.

## Upgrade

Update the plugin and runtime together to v0.55.2. Nothing else to do.

## Details

v0.55.0 started recording each pull request's real base branch. Rounds recorded before that carry no such record. When one of those older rounds exists at the commit being reviewed, the runtime refuses to buy another review of the same commit. The point is to stop a record upgrade from paying for a second review of work that was already reviewed.

That refusal also caught rounds that never reviewed anything: rounds that were charged but lost the browser before any conversation existed, so no answer, captured text or conversation was ever recorded. Those pull requests stayed blocked at their current commit with `stop-without-new-review` / `invalid-binding`.

The refusal now applies only when the older round left something behind that is, or could still become, a review:
- captured, pending or recovered review text;
- a recorded result;
- a remembered conversation, including one later found to belong to another run.

A round that left none of these reviewed nothing, so the next query grants a normal review. That review records the real base, and the older round's charge still counts toward the round budget.

Captured text and results are kept indefinitely, so a round that left one never becomes a reason to pay again. A remembered conversation is kept for 14 days, the same horizon after which pro-gate treats any uncollected conversation as abandoned. After that, a round whose only trace was that conversation is treated like one that left nothing. Pro-gate otherwise keeps only the newest 200 remembered conversations, so an older round's memo is exempt from that limit; no new round records the old format, so the exempt set only shrinks. A remembered conversation can also be withdrawn early, when a check finds another run's answer in it. For an older round, that memo is now moved aside with its original timestamp instead of deleted, so it still counts until its own 14 days are up.

Something can appear after a review is granted, for example a late recovery finding the older round's conversation. So the runtime checks the refusal again at each point before it charges and submits, and it stops there without spending.

Separately, v0.55.1 bounded every browser request by the search's deadline. The last scan of a search can start a moment before that deadline, and its tab listing was cut off almost at once. The search then reported the browser as down, instead of the result its earlier scans had already established. A listing started that late now gets one second to answer. Continuous integration hit this twice on the v0.55.2 pull request.

## Fixed

- A charged pre-v0.55 round that never reached a conversation blocked every new review at the same commit (#226).
- Once the refusal depended on what an older round left behind, a record that appeared after the grant could still let the review be charged; every pre-charge check now repeats it (#227 review round 2).
- The newest-200 limit on remembered conversations could drop an older round's only record well within its 14 days, reopening a paid replacement review (#227 review round 2).
- A quick status check that found another run's answer in an older round's remembered conversation withdrew that memo without keeping any record, reopening a paid replacement review; so did a rejected capture (#227 review round 3).
- A salvage or probe pass whose final tab listing started just before its deadline could report `browser-down` instead of its decisive result (v0.55.1 regression, #227).

# v0.59.0

## Highlights

- A temporary error on one pull request no longer pauses reviews for every other pull request.
- Interrupted recovery keeps the conversation information it needs instead of losing it after a storage error.
- Failed deliveries no longer restart just because their history or Oracle version could not be read.

## Upgrade

Update the plugin and runtime together to v0.59.0. Pinned callers, including the pi extension and Windows/Codex bridge, must use the matching contract and corpus identity before unattended reviews resume. The coordinated consumer update is tracked in [dotfiles #1434](https://github.com/StartupBros-com/dotfiles/issues/1434).

Existing review bindings and older disposition records remain readable by v0.59.0. Downgrading is not seamless: v0.58.0 does not understand the new disposition format or bindings written with the new contract identity. Finish or collect work started under v0.59.0 before a rollback, and preserve the recovery state rather than deleting it to get another grant.

## Details

A failed query, malformed response, or stale target now defers only the affected pull request. A positively identified runtime or contract incompatibility still blocks the daemon until a compatible deployment is available.

Conversation revocation keeps a unique claimed generation until its bytes can be safely rejected or restored. The claim carries the rejected URL's fingerprint in a bounded filename, so a failed blacklist write alone does not make that URL trusted again, even through another claim for the same run. The claim is kept until the blacklist records the rejection: as the URL when the remembered conversation or a remaining claim holds it, otherwise as the claim's fingerprint, so a copy another process publishes later stays rejected. v0.58.0 ignores fingerprint lines. If neither the blacklist nor the claim can be written, the conversation is rejected again the next time it is collected. A rejected conversation that another process remembered again is dropped on the next recall, so its run can finish instead of waiting on a conversation every scan skips. Unreadable directories, oversized files and special files remain uncertain rather than proving absence. Recovery and pruning preserve owned handles, including those whose legacy binding cannot be read, and resolved legacy receipts retain the original memo's expiry clock. Final nonce acceptance remains exact and case-sensitive.

When an attempt is proven never sent, its required durable terminal disposition records the attempt-time delivery condition and either a known count or explicit uncertainty before the round is refunded. Failure of the optional compatibility sidecar cannot erase that evidence. Interrupted cleanup reuses the published evidence instead of recomputing it. Unknown-send attempts remain charged; account challenges remain a separate cooldown path.

The typed decision distinguishes `known`, `unavailable`, and `legacy-untracked` delivery state. Unavailable history or identity returns `delivery-state-unavailable` with a null count. A missing sidecar beside an older v1 disposition remains a documented compatibility exception: its absence cannot distinguish truly old history from a failed write. Learning a previously unknown Oracle version alone is not proof that the build changed.

An operator's `PRO_GATE_ROUNDS_CONTINUE=1` now bypasses the churn brake consistently, but does not enlarge an enforced numeric grant or bypass exhausted and zero budgets. It remains stateless, not a durable one-use allowance. FORCE retains its separate behavior and cannot bypass unavailable delivery evidence. Neither override may be set automatically by an agent.

Trusted CI now fails on malformed JSON or YAML and runs adapter conformance plus fault regressions for these paths. The repair also corrects active documentation that described unimplemented failure classes as shipped behavior.
